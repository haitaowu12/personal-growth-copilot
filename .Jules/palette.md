## 2026-10-14 - Accessible groupings for dynamically rendered checkboxes
**Learning:** When generating a list of related checkboxes dynamically (e.g. self-review criteria), wrapping them in a `<div role="group">` and binding it to an existing heading and description using `aria-labelledby` and `aria-describedby` provides semantic context without altering layout styling (unlike `fieldset`/`legend` which often conflict with existing CSS resets).
**Action:** Always group dynamically rendered multiple-choice or checkbox lists with `role="group"` and proper ARIA labels to ensure screen readers announce the shared context before the individual items.
## 2026-10-17 - Visually hidden inputs breaking layout on focus
**Learning:** A common accessibility pattern for custom file inputs—hiding the native input and styling its adjacent label—can cause severe layout issues when the hidden input receives keyboard focus if the input is made `position: static` dynamically on focus to satisfy screen reader focus rules. The intended `focus-within` styles on the custom label fail because a sibling input doesn't trigger `focus-within` on the label.
**Action:** Instead of using an adjacent visually-hidden input (`label + input`), wrap the visually-hidden input *inside* the label (`<label><input></label>`). This implicit association allows the label to correctly receive `focus-within` styles when the keyboard focuses the input, providing an elegant focus ring without having to reveal the ugly native file input or break layout.
## 2023-10-21 - Focus loss when elements disable themselves
**Learning:** When an interactive element like a button disables itself upon being clicked (e.g., a "Give me a hint" button that only allows a single click), keyboard focus drops to the document body because the disabled element can no longer hold focus. This creates a confusing experience for screen reader users and keyboard navigators.
**Action:** When an element disables itself, programmatically move focus to a logical next step or revealed context (e.g., the newly shown hint text). Give the target element `tabIndex="-1"` so it can receive programmatic focus, and optionally `outline: "none"` if it's purely textual content where a focus ring isn't visually appropriate.
