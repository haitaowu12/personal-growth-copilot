## 2024-10-16 - Character Counter and DescribedBy Accessibility Pattern
**Learning:** For character-limited textareas, visually displaying the constraints is good UX, but to achieve a fully accessible experience, semantic linkage is needed. Linking instructional paragraph text AND the dynamically updating character counter directly to the input via `aria-describedby` provides critical ongoing context to screen reader users. Also providing `aria-live="polite"` makes sure they stay continuously informed.
**Action:** Consistently combine visible constraint feedback (like char counters) with instructional elements, and bind both to the related input control using `aria-describedby` with `aria-live`.
## 2024-10-16 - A11y and Chatty Regions
**Learning:** Avoid using `aria-live` on frequently updating inputs (like keystroke-bound character counters) because it causes screen readers to constantly interrupt the user. `aria-describedby` alone is sufficient for character counts as the user will hear it when the focus enters the element. Also, using inline CSS limits responsiveness and style reuse, keep using available global classes rather than injecting explicit inline styles.
**Action:** Be mindful of adding `aria-live` unnecessarily. Rely on semantic association instead of explicit chatty updates when linking elements like counters, and avoid inline styles where `meta` or existing classes suffice.
